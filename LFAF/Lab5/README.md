## Theory

A **Context-Free Grammar (CFG)** is in **Chomsky Normal Form (CNF)** if every production rule is of one of two forms:

- **A → BC** — a non-terminal produces exactly two non-terminals
- **A → a** — a non-terminal produces exactly one terminal

CNF is useful because it simplifies many algorithms (e.g. CYK parsing). Any CFG without ε can be converted to CNF through a sequence of normalisation steps. The conversion does not change the language generated by the grammar (except possibly for the empty string).

The five normalisation steps applied in order are:

1. **Eliminate ε-productions** — remove rules of the form A → ε by finding all nullable symbols and generating alternative productions without them.
2. **Eliminate unit productions** — remove rules of the form A → B (a single non-terminal) by substituting the full set of B's rules directly.
3. **Eliminate inaccessible symbols** — remove any non-terminal (and its rules) that cannot be reached from the start symbol.
4. **Eliminate non-productive symbols** — remove any non-terminal that can never derive a string of terminals.
5. **Convert to CNF** — replace terminals in long rules with fresh non-terminals, then break rules with 3+ symbols into binary rules by introducing auxiliary non-terminals.

## Implementation Description

The grammar is represented as a Python dictionary with four keys: `N` (set of non-terminals), `T` (set of terminals), `P` (dict mapping each non-terminal to a list of RHS strings), and `S` (start symbol). Each step is a pure function that takes a grammar dict and returns a new one, leaving the original unchanged.

### Step 1 — `eliminate_epsilon`

First, all nullable symbols (those that can derive ε) are found using a fixed-point loop. Then, for every production, all subsets of nullable symbol positions are generated using `itertools.combinations`, and new productions are created with those symbols removed. The original ε-rules are dropped.

```python
def eliminate_epsilon(grammar):
    nullable = set()
    for nt, rules in P.items():
        if '' in rules:
            nullable.add(nt)
    # propagate nullability
    changed = True
    while changed:
        changed = False
        for nt, rules in P.items():
            for rhs in rules:
                if rhs and all(sym in nullable for sym in rhs):
                    nullable.add(nt); changed = True
    # generate combinations without nullable symbols
    for nt, rules in P.items():
        for rhs in rules:
            nullable_positions = [i for i, sym in enumerate(rhs) if sym in nullable]
            for r in range(len(nullable_positions) + 1):
                for combo in combinations(nullable_positions, r):
                    new_rhs = ''.join(sym for i, sym in enumerate(rhs) if i not in combo)

```

### Step 2 — `eliminate_unit_productions`

For each non-terminal, the function computes the **unit closure** — the set of all non-terminals reachable via a chain of unit rules (A → B → C → ...) using BFS. Then all non-unit productions from every reachable NT are copied directly into the source NT's rule list.

```python
def unit_closure(nt):
    visited = {nt}
    queue = [nt]
    while queue:
        cur = queue.pop()
        for rhs in P.get(cur, []):
            if len(rhs) == 1 and rhs in N and rhs not in visited:
                visited.add(rhs); queue.append(rhs)
    visited.discard(nt)
    return visited
```

### Step 3 — `eliminate_inaccessible`

A BFS from the start symbol S marks every non-terminal that appears on the RHS of any reachable rule. Any NT not marked is inaccessible and removed along with all its productions.

```python
reachable = {S}
queue = [S]
while queue:
    nt = queue.pop()
    for rhs in P.get(nt, []):
        for sym in rhs:
            if sym in N and sym not in reachable:
                reachable.add(sym); queue.append(sym)
```

### Step 4 — `eliminate_nonproductive`

A non-terminal is productive if it can eventually derive a string of only terminals. The function seeds productive NTs (those with an all-terminal RHS) then propagates: a NT is productive if any of its RHS strings consist only of terminals and already-productive NTs. Non-productive NTs and any rule mentioning them are removed.

### Step 5 — `to_cnf`

Done in two sub-steps:

**5a** — for every rule of length ≥ 2, each terminal `t` is replaced by a fresh non-terminal `Tt` (e.g. `a` → `TA`, `b` → `TB`), with `TA → a` added. This ensures that long rules contain only non-terminals.

**5b** — rules with 3 or more symbols are binarised right-to-left: the last two symbols are replaced by a fresh `Xi` non-terminal with rule `Xi → last two symbols`, and the process repeats until every rule has exactly two symbols.

```python
while len(syms) > 2:
    new_nt = fresh_nt()          # X1, X2, ...
    new_P[new_nt] = [''.join(syms[-2:])]
    syms = syms[:-2] + [new_nt]
```

## Conclusions / Screenshots / Results

Starting grammar (Variant 11):

```
S → bA | AC
A → bS | BC | AbAa
B → BbaA | a | bSa
C → ε
D → AB
```

**After Step 1** (ε-elimination, C was nullable):
```
S → bA | AC | A
A → bS | BC | B | AbAa
B → BbaA | a | bSa
D → AB
```
Note: C → ε removed; S → A and A → B (unit productions) introduced.

**After Step 2** (unit productions eliminated):
```
S → bA | AC | bS | BC | AbAa | BbaA | a | bSa
A → bS | BC | AbAa | BbaA | a | bSa
B → BbaA | a | bSa
D → AB
```

**After Step 3** (D is inaccessible, removed):
```
S → bA | AC | bS | BC | AbAa | BbaA | a | bSa
A → bS | BC | AbAa | BbaA | a | bSa
B → BbaA | a | bSa
```

**After Step 4** (C is non-productive — no rules left — removed):
```
S → bA | BbaA | a | bSa | bS | AbAa
A → bS | AbAa | BbaA | a | bSa
B → BbaA | a | bSa
```

**After Step 5** (CNF):

Every rule is now either A → BC or A → a. Long rules were binarised right-to-left using auxiliary non-terminals X1–X32, and terminals in mixed rules were replaced by TA → a and TB → b.

Sample CNF rules:
```
A → TB X21 | A X25 | B X29 | a | TB X32
B → B X17  | a     | TB X20
S → TB X1  | B X5  | a     | TB X8 | TB X9 | A X13
TA → a
TB → b
X1  → B A
X9  → B S
X17 → TB X16   (expanding BbaA chain)
...
```

The main challenge was correctly handling the interaction between steps: ε-elimination introduced new unit productions that then needed to be removed in step 2, and C became non-productive only after its ε-rule was removed, which was only caught in step 4. This confirms that the steps must be performed strictly in order.
